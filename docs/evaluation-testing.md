# 评教功能开发与验证

本次改动以原仓库 main 的 `f9ea529`（v0.3.2）为基线。

## Android skills 的应用范围

参考 Google 官方 [android/skills](https://github.com/android/skills/tree/4ebabf2b0fd6c04b7150023c8b612f80592a6226)：

- `jetpack-compose/jetpack-compose-performance` 及 `references/lazy-layouts.md`：评教页 LazyColumn 使用可保存的稳定 key 和 contentType，继续在页面统一收集 StateFlow；不为含集合的状态模型添加稳定性注解。
- `testing/testing-setup`：沿用现有 JUnit4、kotlinx-coroutines-test；抽取 EvalDataSource 接口，在 JVM 测试中使用 fake，避免调用真实学校接口。此次只应用与功能相关的单元测试建议，不扩展为整个项目的测试框架迁移。

评分、必答题校验和提交答案构造统一放在 EvalFormLogic 中，单份表单和批量操作共享规则。EvalBatchRunner 负责顺序、刷新、跳过和停止，ViewModel 负责状态与生命周期。

## 批量提交边界

- EvalRequestGate 在整个 App 的同一个 jwqe 客户端中统一串行请求。读请求至少间隔 1000–1250ms，写请求至少间隔 2000–3000ms，失败后同样计入。关闭 OkHttp 隐式重试和重定向，仓库层的读取重试重新经过节流。
- HTTP 或业务码 429/403/503，以及状态消息中的“操作频繁/请稍后再试”等提示均停止当前流程（即使 code=200 也不能当成功）；最低冷却通常为 60 秒，403 为5分钟，Retry-After 秒数或 HTTP 日期更久时采用更久值。不自动唤醒重试。下一次可请求时间及冷却截止时间写入 SharedPreferences，重启后继续生效。
- 预览只读，最多发现 10 个任务、100 门课程；教师列表最多 20 页。显示待评课程、预计待评教师、未知教师数量的课程和受保护对象数。尚未提交的合讲课程不能保证教师数精确，界面明确标注。每次确认最多写入 20 项，之后需再次预览。
- 任务按 taskid 去重；对象按任务、课程代码、学期、课程类型、班号、教师身份及学生信息区分，不依赖会变化的结果 ID。分页重叠保留已评/草稿证据；预览及按任务/父课程缓存直接跳过已评、草稿与历史记录；只在真正准备写入的对象提交前刷新一次列表，并将结果更新到缓存。题目按指标体系和课程类型复用。只处理本次预览中的课程，不自动吸收新增任务/课程。
- 服务端草稿不参与自动填写。手动与批量提交共用仓库日志。按账号和对象在进程内认领，只有通过认证、冷却、连接准备之后，才在网络拦截器发出请求头前同步记录 SENT；成功业务响应记录 CONFIRMED。发送前失败或取消只释放认领，不能污染持久记录；SENT 后结果不明才保留保护。SharedPreferences 的 commit 失败会恢复内存旧值并阻止发请求。旧版布尔标记不能确认是否发送，保守迁移为 SENT。结果不明的记录需打开单份表单手工核对，批量流程不会清除标记或自动恢复。日志只保存身份摘要，不保存账号明文、凭证或评语。记录不能代替服务端幂等机制；其他客户端并发操作仍可能竞争，最终状态以学校接口为准。
- 单份提交、批量执行和预览期间消费系统返回事件；单份提交的工具栏返回同样禁用。不能防止操作系统杀进程，因此批量尝试记录仍必需。

## 验证命令

需要 JDK 17、Android SDK platform 36 和 build-tools 36.0.0：

```sh
cd kcb-app
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

GitHub Actions 的 Android checks 执行同样检查并保存报告和 debug APK。测试不连接真实账号，不会代用户提交评价。

## 回归范围

- 自动填写成功时无 Snackbar；评分限制、降档候选不足时的失败提示仍有效。
- 普通课程、合讲课程、多个教师、已评父课程下未评教师。
- 所有进行中的打分任务，以及仅当前任务；跳过已结束和不支持的任务类型。
- 草稿跳过、非计分必答题、未知题型、服务器状态更新延迟。
- 单次上限、只读预览、重复任务/对象与教师分页重叠、提交前新出现的草稿/已评状态、未知写入结果再次运行时保持受保护。
- 100门课程或100名教师仅1项待评时，对应列表只查询2次（预览+写前刷新）；发送前失败可重新认领、并发认领互斥；手动成功后批量仍受日志保护；本地 HTTP 服务确认钩子在请求头之前执行、钩子失败不发请求头。
- 并发读写共享预算、失败节流、429 Retry-After、403 最低冷却以及重建节流对象后继续冷却。
- 提交失败不重试、不继续下一项；停止时保留当前请求结果，协程取消正常向上传播。

真机还需验证不同屏幕尺寸、返回与旋转、进度区域和停止按钮。真实学校接口的行为与最终评价状态仍需使用者核对，JVM fake 测试不能证明线上提交成功。
